# broll-zoom toolkit

Рабочие прототипы к стратегии v6.2 (b-roll-first + планы камеры + субтитры).
Эталонный ролик собран ИМЕННО этими скриптами вручную; в пайплайне логики пока
нет. Задача интеграции описана в `docs/HANDOFF-BROLL-ZOOM-V6.md`.

## Что здесь

| Файл | Что делает |
|---|---|
| `broll_context_retrieval.py` | подбор b-roll по фразе + контексту сценария + анти-контексту; источники Pexels / Pixabay / Coverr / локальная библиотека; ранжирование CLIP по кадрам |
| `camera_plan.py` | режет речь на планы 1.2–3.9с, назначает зумы (push_in / static), вспышки, генерирует ASS-субтитры в утверждённом стиле |
| `measure_zoom.py` | численная проверка: реально ли применился зум и есть ли вспышки |
| `build_reference.sh` | сборка эталонного ролика из аватара, b-roll серий, зум-выражения и субтитров |
| `reference/` | согласованный результат: план b-roll, планы камеры, выражения зума и вспышек, .ass, words.json, пример входа для подбора |

## Порядок запуска (воспроизвести эталон)

```bash
# 1. планы камеры + субтитры из пословного alignment
python camera_plan.py --words reference/words.reference.json --duration 32.4 --out-dir work/

# 2. подбор b-roll (нужны ключи в env или файлами, см. docstring скрипта)
python broll_context_retrieval.py --windows reference/windows.example.json \
       --out work/picks.json --dl-dir work/broll_dl

# 3. собрать серии по 2 клипа с переходом внутри (команда в конце build_reference.sh),
#    затем финальная сборка
AVATAR=avatar.mp4 VOICE=voice.mp3 WORK=work ./build_reference.sh out.mp4

# 4. проверить зум и вспышки числами, а не глазами
python measure_zoom.py out.mp4 --pairs 4.5,3.5 4.5,7.5 4.5,13.0 --flash-at 3.78 16.58
```

## Зависимости

- Python: `torch`, `open_clip_torch`, `transformers`, `pillow`, `numpy`
  (CLIP-модель `xlm-roberta-base-ViT-B-32`, pretrained `laion5b_s13b_b90k`;
  первый запуск тянет ~1 ГБ весов в кэш HF)
- `ffmpeg` 7+ с `libass` (для фильтра `subtitles`)
- Модуль `reels_factory.broll_library` из движка (путь задаётся `--engine-src`)

## Ключи стоковых API

Читаются из переменных окружения `PEXELS_API_KEY`, `PIXABAY_API_KEY`,
`COVERR_API_KEY`, либо из файлов в `--keys-dir`. В репозиторий ключи не кладём.

Что дают источники на практике (прогон 2026-08-03, 18 запросов на каждый):

| Источник | Результатов | Вертикальных | Попало в монтаж |
|---|---|---|---|
| Pexels | 72 | 72 (серверный фильтр `orientation=portrait`) | 6 из 6 |
| Pixabay | 540 | 21 (фильтра ориентации нет, режем сами по width/height) | 0 |
| Coverr | 17 | 0 (флаг `is_vertical` есть, но вертикали в базе почти нет) | 0 |

Вывод: рабочий источник один — Pexels. Остальные держим как запасные, но
отсекать горизонталь надо ДО скачивания, иначе тянутся сотни мегабайт впустую.

## Грабли, на которые уже наступили

1. **Два вызова `pow()` в выражении `z` ломают `zoompan` молча.** Ошибки нет,
   рендер проходит, зум схлопывается в 1.0. Ease-out писать как `p*(2-p)`.
2. **Зум нельзя проверять глазами.** Спикер сам наклоняется к камере, и на
   стоп-кадрах это читается как наезд. Две версии были сданы с неработающим
   зумом. Только `measure_zoom.py`.
3. **Дельта зума меньше 14 п.п. не читается.** Рабочее: 100 → 118% за ≤1.5с.
4. **Фильтр `subtitles` на Windows ломается о `C:` в пути** — запускать ffmpeg
   из каталога с `.ass` и шрифтом, передавать относительные пути.
5. **Pexels без заголовка `User-Agent` отдаёт 403.**
6. Замерять зум только там, где в кадре аватар: под b-roll замер бессмыслен.
