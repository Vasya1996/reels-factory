# ТЗ · Визуальный критик (слой 4) + прогон на avatar-bot-poc

Дата: 2026-08-03. Бюджет: только LLM-vision вызовы (1–3 шт), HeyGen/ElevenLabs — 0.
Прод не трогать. Код блоков/компилятора в этом ТЗ не менять (исключение —
сам скрипт критика).

## Что строим

`compiler/critic.mjs` — детерминированная обвязка вокруг 1 vision-вызова:

1. **Снапшоты**: для каждой сцены плана 2 кадра — `scene.start+0.4` и
   середина сцены (через `npx hyperframes snapshot --at ...` по
   render-project/, либо playwright-скрин композиции с сиком таймлайна).
2. **Один vision-вызов** (Claude, все кадры разом + план + текст речи
   по сценам). Промпт критика = ФИКСИРОВАННЫЙ чек-лист из правил
   NEXT-SESSION.md v3–v5, по каждой сцене ответить да/нет:
   - пустая композиция: раскладка отжала место, а контента нет (пр. 8);
   - текст в кадре без функции: «что зритель потеряет, если стереть?» (пр. 9);
   - мета-слова/категории в кадре (пр. 3);
   - заголовок дублирует субтитры (>60% слов) (пр. дубля);
   - приём противоречит смыслу речи сцены (хаос-облако на позитивном
     перечислении и т.п.);
   - графика опережает слова (пр. 4) — по паре кадров начало/середина;
   - мёртвый простой в начале сцены (пр. 6);
   - fullscreen: ≥2 TRUE-fullscreen, хук fullscreen (пр. 7);
   - текст обрезан/вылез/перекрыт, субтитры на контенте;
   - hook: заголовок = суть первой фразы или null, не абстракция (пр. 1).
3. **Выход критика — строгий JSON**: массив находок
   `{scene_id, rule, evidence, fix_op}`, где `fix_op` ТОЛЬКО из меню:
   `set_block(name)` · `set_headline(null|text)` · `remove_label(idx)` ·
   `set_label_trigger(idx, word_index)` · `move_boundary(scene, ±sec)` ·
   `set_captions(hidden|bottom)` · `set_transition(name)` · `report_only`.
   Никакого кода, никаких новых сущностей. Что не чинится меню —
   `report_only` в отчёт.
4. **Применение**: операции применяются к project-avatar-bot/edit_plan.json,
   валидатор → компиляция → новые снапшоты → второй vision-прогон.
   Максимум 2 круга. После второго — стоп в любом состоянии.
5. **Отчёт Юлии**: markdown — находки круга 1, применённые операции,
   находки круга 2, что осталось report_only, скрины до/после по
   изменённым сценам + пересобранный MP4.

## ВАЖНО: слепой тест

У Юлии есть 2 известных замечания к этому ролику. В промпт критика их
НЕ включать, никаких намёков. После круга 1 сравнить находки критика с
файлом `TZ-CRITIC-expected.md` (создать ДО прогона, содержимое ниже) и
написать в отчёте: нашёл / не нашёл каждое.

Содержимое TZ-CRITIC-expected.md (создать до запуска критика, критику
не показывать):
1. s02: bubble-раскладка с пустой левой частью (нет контента) — правило 8.
2. s05: слово «БОТ» в углу без функции — правило 9.

Если критик не нашёл одно из двух — чек-лист в промпте слабый, усилить
формулировку соответствующего пункта и прогнать круг 1 заново (это не
считается за круг).

## Критерий успеха

- Оба известных дефекта найдены критиком самостоятельно.
- Все fix_op — из меню, план после правок проходит validate-plan.mjs.
- Итоговый MP4 без пустых композиций и текста-этикеток.
