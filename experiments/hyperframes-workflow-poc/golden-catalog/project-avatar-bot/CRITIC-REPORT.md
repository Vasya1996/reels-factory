  "не считается за круг").

  сломанные» сцены) и 2 (отдельный вопрос по каждому текстовому элементу,
  включая одиночное слово-название в углу).
- **Вызов 2** (тот же круг 1, усиленный чек-лист): **оба известных дефекта
  найдены самостоятельно**:

## Что НЕ применено и почему (курирование)

**Небезопасно (сломало бы валидатор):** `set_block(avatarFullscreen)` для
s02/s03/s04/s07 — `avatarFullscreen` уже использован дважды (s01, s05, лимит
диверсити — максимум 2 за ролик); для s02 это ещё и соседняя с s01 сцена
(запрещены одинаковые блоки подряд). Применение сломало бы уже пройденный
`validate-plan.mjs`. Отдельно: критик путает `avatar_direction: "fullscreen"`
(лицо крупно, в капсуле — так задуман `complexityCloud`) с TRUE-fullscreen
блоком (`avatarFullscreen`/`avatarFullscreenCta`, видео на весь кадр без
рамки, правило v4 №7) — это два разных понятия с одинаковым словом.

**Ложные срабатывания (спутали приём с багом):** `remove_label` для s03
(×3 в круге 2), s04, s07 (×2) — критик принял НАМЕРЕННЫЙ приём («стикер
слова-из-речи → то же слово чуть позже в субтитрах» — так спроектированы
`avatarBubble`/`complexityCloud` по правилу v3 №5, подтверждение сказанного)
за дубль-баг. Это не то же самое, что находка s05: там заголовок-одиночка
был чистой декорацией без другой функции; здесь лейблы — единственный
несубтитровый контент сцены, визуально подтверждающий речь. Не применено.

**Требует контента, которого нет в меню fix_op:** s02 (пустая
bubble-колонка) — единственный «менюшный» способ починить пустоту без
нарушения диверсити-лимита (`set_block` на другой блок с 0 обязательных
labels) недоступен: `avatarFullscreen`/`complexityCloud` уже на лимите.
Значит, честный менюшный фикс отсутствует → **report_only**, вынесено в
рекомендации ниже.

**report_only критика (s06 пустая композиция, phoneCase)** — согласна с
наблюдением, но меню не содержит операции «добавить контент», починить
нечем → остаётся report_only.

## Круг 2 — находки после фикса (12 шт., пересняты кадры)

Полный файл в диалоге (не сохранён отдельным JSON — по итогам ни одна
находка не оказалась новой и безопасно применимой). Кратко:

- Повтор s02/s03/s04/s07 «пустая композиция» — те же выводы, что в круге 1
  (report_only, см. выше).
- **Новое, содержательное:** s07 правило 5 — `complexityCloud` уже
  использован в s03 как метафора «перегруза» («НЕТ ВРЕМЕНИ»), а в s07 тот
  же приём подан для payoff-сцены («ГОТОВО») — визуальный язык «сложности»
  противоречит смыслу «всё уже сделано». Это ровно пример из самого ТЗ
  («хаос-облако на позитивном перечислении»). Согласна, что это тонкое, но
  реальное расхождение — но починить в рамках меню (`set_block` упирается в
  тот же диверсити-лимит) не могу → **report_only, рекомендую творческое
  решение Юли** (например, другой блок для одного из двух эпизодов, если
  будет расширяться каталог скомпилированных блоков).
- Два новых `set_label_trigger` (s03/label0, s07/label0) с обвинением
  «графика опережает слово» — **проверила по кадрам лично: неверно.**
  На frame-04 круга 2 (s03, старт 5.89s) и на frame-12 (s07, старт 21.7s)
  субтитры и лейбл появляются в один момент (оба завязаны на одно и то же
  `word.start`), не с опережением — критик ошибся при чтении кадра. Не
  применено.

## Что осталось report_only (для Юли)

1. **s02** — пустая левая колонка bubble-раскладки (labels: []). Менюшного
   фикса без нарушения лимитов блоков нет. Варианты на твой вкус: добавить
   1-2 пилюли (контент из тех же слов сцены) вручную, либо в промпте
   director завести guard-рейл «avatarBubble без labels — только если
   headline визуально занимает объём колонки».
2. **s04** — то же самое, но там уже есть 2 пилюли — вопрос не в пустоте
   лейблов, а в том, что критик посчитал занятую площадь <30% кадра;
   субъективно, можно оставить как есть.
3. **s06 (phoneCase)** — на старте сцены кадр почти пуст (аватар — маленький
   кружок, карточка чата появляется только к середине). Можно сдвинуть
   появление первой реплики чата раньше (было бы `move_boundary` или
   правка тайминга внутри блока — вне менюшных операций уровня плана).
4. **s07 vs s03** — оба используют `complexityCloud`, визуальная метафора
   «перегруза» повторно применена к позитивной payoff-сцене. Творческое
   решение за тобой.

## Правки по итогам круга 2 (NEXT-SESSION.md, пп.10-15) — v3

10. **avatarFullscreen вне лимита разнообразия** — `validate-plan.mjs`:
    `DIVERSITY_UNLIMITED_BLOCKS = {avatarFullscreen, avatarFullscreenCta}`,
    исключены из проверки «≤2 раза» (соседство всё ещё запрещено).
11. **`add_label(text, trigger_word_index)` в меню критика** — `critic.mjs`:
    добавляет label в нужном формате (объект с trigger для обычных блоков,
    голая строка для EXEMPT_BLOCKS).
12. **`taskList` в компиляторе** — новый блок в `blocks.mjs` (по образцу
    `blocks/g08-task-list`): чек-лист с галочкой ✓, мини-PiP аватара сверху
    справа (держит avatar-first). **s07 переключён** с `complexityCloud` на
    `taskList` — закрывает семантическое расхождение из круга 2 (метафора
    перегруза vs позитивный payoff).
13. **Правило 6 внутри блока** — `validate-plan.mjs`: новый
    `BLOCK_BASE_OFFSET_SEC` проверяет собственный (не label-триггерный)
    первый элемент блока против 1.2с. **Нашла реальный баг по ходу**:
    `avatarFullscreenCta` печатала @handle-стемп на `+1.4с` (>1.2с) —
    поправила на `+0.9с` в `blocks.mjs`.
14. **Автокурирование** — `critic.mjs apply` переписан: каждый `fix_op`
    (кроме `report_only`) пробуется на копии плана и коммитится, только
    если `validate-plan.mjs` возвращает 0 FAIL; иначе — откат, причина
    валидатора попадает в отчёт. Ручное курирование (как было в v2) больше
    не требуется.
15. **Постоянное уточнение чек-листа** — вшито прямо в `FIXED_CHECKLIST`:
    labels со словами из речи сцены — подтверждение (правило 5), не дубль;
    дубль — только декоративный элемент без второй функции.

**Побочная находка при ручной проверке `taskList`:** галочка ✓ (`data-anim="tick"`)
никогда не отображалась ни в одном блоке, использующем этот тип анимации
(включая `beforeAfter`, ранее не проверенный вживую) — баг компилятора:
GSAP `.from()` резолвил "to"-состояние для `scale`/`rotation` в то же
значение, что и "from" (класс `.tick` уже имеет `scale(.4) rotate(-20deg)`
по умолчанию), давая no-op тween. Заменила на `.fromTo()` с явным "to" в
`compile.mjs`. Один фикс чинит оба блока.

## Круг 3 (после правок 10-15) — новый слепой прогон

Пересобрала снапшоты, запустила нового слепого критика с обновлённым меню
(включая `add_label`) на **уже другом плане** (s07 = taskList). Находки —
7 шт., **критик снова не воспользовался `add_label`** (все report_only):
повторы пустых композиций s02/s03/s04/s06/s07 (те же, что и раньше, критик
их видит стабильно) + 2 новых «графика опережает слово» (s03 label
«продукт», s04 label «в соцсетях»).

**Проверила обе «опережения» лично по кадрам — обе неверны** (тот же
паттерн ошибки, что и в круге 2): на frame-04 (s03, start@5.89s) лейбл
«продукт» **ещё не показан** — субтитры идут только «ПОКА СТРОИШЬ»,
метка появляется позже, синхронно со словом. На frame-06 (s04,
start@10.14s) лейбл «в соцсетях» появляется **синхронно** с субтитрами
«А В СОЦСЕТЯХ», не раньше. Критик путает "рано в СЦЕНЕ" с "рано
относительно СЛОВА" — не находка.

Прогнала все 7 находок через новое автокурирование (`critic.mjs apply`):
все 7 — `report_only` (сам критик так пометил, автокурирование не имело,
что тестировать на них). **Добавила отдельно 1 инженерную демонстрацию**
`add_label` (не находка критика, я сама): `s02` — `add_label(не отличить, 13)`,
слово из речи именно этой сцены. Автокурирование приняло (прошло
`validate-plan.mjs`) — s02 больше не пустует (пилюля с текстом из речи
теперь заполняет прежде пустую bubble-колонку).
