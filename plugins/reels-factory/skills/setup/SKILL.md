# Setup — мастер первого запуска

Всё, что ниже, — инструкции ДЛЯ ТЕБЯ (Claude), не для человека: ты сам
выполняешь команды и спрашиваешь у пользователя только то, что не можешь
узнать сам (ключи, фото, тему, продукт). Не показывай пользователю голый
список команд вместо действия — выполняй шаги по порядку. У каждого шага
есть критерий «шаг пройден»; не переходи к следующему, пока критерий не
выполнен. При провале шага — объясни пользователю понятную причину и
конкретное действие для починки, а не сырой трейсбек.

Важная техническая особенность инструмента команд: КАЖДЫЙ вызов
shell-команды (Bash/PowerShell) — это НОВЫЙ процесс, переменные окружения
(`$env:...`), заданные в одном вызове, НЕ переживают до следующего вызова.
Поэтому там, где ниже нужен ключ API, задавай его В ТОМ ЖЕ вызове, что и
саму команду (одна команда через `;`), не полагайся на ранее выставленный
`$env:`.

Вторая особенность — кодировка консоли PowerShell по умолчанию НЕ UTF-8:
если команда печатает в stdout русский текст (тема, реплики сценария,
текст ошибки), ты можешь увидеть в выводе абракадабру вместо кириллицы,
хотя сам файл на диске записан правильно (в UTF-8). Там, где это важно
(шаг 8 ниже, и аналогично в research/script/make), добавляй
`$env:PYTHONUTF8="1"; ` перед вызовом `.venv\Scripts\python.exe` — тогда
русский текст в stdout читается как есть, без искажений.

## Шаг 1. Python ≥3.11 и ffmpeg

```powershell
python --version
```

- Напечатала версию ≥3.11 — используй `python` как `PYTHON_CMD` на шаге 3.
- Команда НЕ НАЙДЕНА — частый случай на Windows: официальный установщик
  python.org по умолчанию кладёт в PATH только `py`-лаунчер, а не сам
  `python.exe`. Прежде чем считать Python отсутствующим, проверь лаунчер:

  ```powershell
  py --version
  ```

  Напечатал версию ≥3.11 — используй `py` как `PYTHON_CMD` на шаге 3
  (команда венва там — `py -m venv .venv`, лаунчер сам находит нужный
  интерпретатор).
- Ни `python`, ни `py` не нашлись, либо версия <3.11 — попроси пользователя
  выполнить `winget install Python.Python.3.12` и сообщить, когда готово;
  после установки открой новый вызов (PATH подтянется в новом процессе) и
  проверь снова (сначала `python`, потом `py`).

```powershell
ffmpeg -version
```

- ffmpeg: если `ffmpeg -version` не печатает `ffmpeg version ...` —
  попроси пользователя выполнить `winget install Gyan.FFmpeg`. Даже если
  PATH в текущей сессии не обновится сразу, это не блокер: движок сам
  находит ffmpeg по фолбэку на путь winget-установки (см.
  `engine/src/reels_factory/config.py::_resolve` — сначала PATH, потом
  глоб по `Gyan.FFmpeg*/**/ffmpeg.exe`). Реальную проверку с фолбэком
  сделаешь на шаге 9.

Критерий: `python --version` ИЛИ `py --version` печатает ≥3.11.x — запомни,
какая из двух команд сработала, это твой `PYTHON_CMD` для шага 3. Если
ffmpeg не нашёлся в PATH — зафиксируй и перепроверь на шаге 9 через сам
движок, не блокируй установку из-за одного PATH.

## Шаг 2. Рабочая папка = ТЕКУЩАЯ папка пользователя

ВАЖНО (см. `engine/src/reels_factory/config.py`): движок вычисляет
`WORK_ROOT` и `FACTORY_DIR` как `Path.cwd() / "work"` и
`Path.cwd() / "factory"` — то есть **привязан к текущей рабочей директории
процесса**. Значит:

- Отдельную папку для проекта создавать не нужно — рабочая папка это ТЕКУЩАЯ
  папка, в которой пользователь открыл Claude Code для этого проекта (cwd
  сессии).
- **Все** команды движка (`python -m reels_factory ...`, а также venv и
  `pip install`) ниже и во всех последующих скиллах (research/script/
  make/review) нужно запускать ИЗ КОРНЯ этой рабочей папки — не из папки
  плагина, не из случайной поддиректории. Если ты когда-либо делаешь `cd`
  куда-то ещё в рамках этой сессии — обязательно вернись в корень рабочей
  папки перед следующей командой движка.

Критерий: ты знаешь абсолютный путь рабочей папки (текущий cwd) и явно
используешь его как рабочую директорию для всех команд ниже.

## Шаг 4. Формат + ключи HeyGen и ElevenLabs

Формат определяет, нужен ли HeyGen и фото, поэтому спроси его В САМОМ НАЧАЛЕ,
до фото и ключей (и раньше остального интервью — на шаге 7 повторно НЕ
задавай). Три формата:

- `split` — аватар-ведущий (HeyGen) сверху 1080×672 + видеоряд снизу. Нужен
  HeyGen; фото — ГОРИЗОНТАЛЬНОЕ (≈1.6:1). Дороже.
- `fullscreen` — только видеоряд на весь кадр, голос ведущего за кадром.
  HeyGen и фото НЕ нужны вообще, вдвое дешевле.
- `avatar` — аватар-ведущий (HeyGen) на весь кадр 1080×1920, голос вшит;
  видеоряд опционален (отдельные вставки поверх аватара). Нужен HeyGen;
  фото — ВЕРТИКАЛЬНОЕ (9:16).

Для первой настройки спроси, с какого языка пользователь хочет начать:

> На каком языке будет первый ролик?

Варианты: `ru` — русский, `kk` — қазақша. Сохрани выбор как активный
`language`; запись/клон голоса на шаге 6 должны быть на том же языке. В
Telegram после каждого `/start` и `/new` язык выбирается для конкретного
ролика. Если позже пользователь выберет второй язык, бот отдельно запросит
голос на нём и добавит его в `voices`, не удаляя первый.

Спроси у пользователя в чате ключ(и):
- `ELEVENLABS_API_KEY` (ElevenLabs → Profile → API Keys) — нужен в любом формате.
- `HEYGEN_API_KEY` (HeyGen → Settings → API) — нужен, если формат `split` или
  `avatar`; для `fullscreen` не спрашивай и не сохраняй его.

Не проси прислать их в файл и не сохраняй ключи никуда, кроме переменных
окружения — они не должны попасть ни в `factory/config.yaml`, ни в git.

Сохрани ключ(и) персистентно (для будущих сессий) И одновременно
подставляй их явно во все последующие команды этого же запуска setup
(см. заметку про «новый процесс на каждый вызов» в начале файла):

```powershell
[System.Environment]::SetEnvironmentVariable("ELEVENLABS_API_KEY", "<ключ>", "User")
```

```powershell
[System.Environment]::SetEnvironmentVariable("HEYGEN_API_KEY", "<ключ>", "User")
```

(вторую команду — только при формате `split` или `avatar`.)

Критерий: команда(ы) `SetEnvironmentVariable` выполнены без ошибок; в
шагах 5/6/9 ключ передаётся В ТОЙ ЖЕ команде, где он нужен (например
`$env:HEYGEN_API_KEY="<ключ>"; .venv\Scripts\python.exe -c "..."`).

## Шаг 5. Аватар: фото → HeyGen v3 asset

Формат `fullscreen` (решили на шаге 4) — HeyGen не нужен вообще, пропусти
этот шаг целиком и переходи сразу к шагу 6 (голос ElevenLabs нужен в любом
формате).

Форматы `split` и `avatar` — спроси у пользователя путь(и) к фото для
аватара-ведущего.

**Ориентация фото зависит от формата** (движок это НЕ проверяет — проверь
здесь сам, чтобы кадр не срезал лицо):
- `split` — аватар занимает верх экрана 1080×672 → фото ГОРИЗОНТАЛЬНОЕ,
  соотношение ≈1.6:1 (ширина больше высоты);
- `avatar` — аватар на весь кадр 1080×1920 → фото ВЕРТИКАЛЬНОЕ, соотношение
  ≈9:16 (высота больше ширины).

Проверь ориентацию фото до загрузки (ширину/высоту можно узнать через ffprobe
или `.venv\Scripts\python.exe`), и если она не совпадает с форматом (например
для `avatar` прислали горизонтальное) — предупреди пользователя и попроси
подходящее фото, не загружай молча.

Общие правила кадра (оба формата):
- точное соотношение НЕ обязательно — движок сам кадрирует под нужный размер
  (`scale=...:force_original_aspect_ratio=increase,crop=...`, см. `compose.py`);
  HeyGen генерирует видео под исходный размер фото (`avatar.py`:
  `_generate_v3`), а финальный кроп делает ffmpeg. Но грубое несовпадение
  ориентации (вертикаль вместо горизонтали) срежет лицо — поэтому проверка
  выше обязательна;
- лицо держи **по центру кадра**;
- взгляд — **«в монитор»** (прямо в камеру), аватар обращается к зрителю.

Загрузи фото в HeyGen `/v3/assets` (тот же endpoint, что использует
`avatar.py` для аудио — генерический аплоад ассетов, поддерживает
png/jpeg) и получи `asset_id`:

```powershell
$env:HEYGEN_API_KEY="<ключ>"; .venv\Scripts\python.exe -c "import os,sys,requests; from reels_factory.avatar import UPLOAD_URL; p=r'<путь к фото>'; k=os.environ['HEYGEN_API_KEY']; r=requests.post(UPLOAD_URL, headers={'X-Api-Key':k}, files={'file':(os.path.basename(p), open(p,'rb').read())}, timeout=60); r.raise_for_status(); print(r.json()['data']['asset_id'])"
```

Если пользователь дал несколько фото — сделай так на каждое и спроси,
какое использовать по умолчанию (можно оставить остальные в памяти как
запасные, но в `config.yaml` идёт только один `heygen_asset_id`).

Критерий: команда напечатала непустую строку `asset_id` (без трейсбека
requests — при 401/403 сообщи пользователю, что ключ неверный, и вернись
к шагу 4).

## Шаг 6. Голос: один голос на выбранном языке

```powershell
$env:ELEVENLABS_API_KEY="<ключ>"; .venv\Scripts\python.exe -c "import os,requests; k=os.environ['ELEVENLABS_API_KEY']; r=requests.get('https://api.elevenlabs.io/v2/voices', headers={'xi-api-key':k}, params={'page_size':100}, timeout=60); r.raise_for_status(); vs=r.json()['voices']; ru=[v for v in vs if any((l.get('language')=='ru') for l in (v.get('verified_languages') or []))]; pick=ru or vs; [print(v['voice_id'], '-', v['name']) for v in pick[:15]]"
```

Для `kk` замени фильтр `ru` в команде на `kk`. Из напечатанного списка выбери
3-5 голосов и предложи пользователю в чате
в формате «имя — voice_id» (если явно русских голосов (`ru` в
`verified_languages`) не нашлось — предупреди, что показываешь
мультиязычные голоса ElevenLabs, они всё равно озвучивают русский текст
через модель `eleven_v3`, но акцент стоит проверить на слух — тестовый
прогон будет на шаге 9). Запиши выбранный `voice_id`.

Если пользователь УЖЕ назвал конкретный `voice_id` сам (знает его заранее,
например из своего кабинета ElevenLabs) — не гоняй список, сразу возьми
его.

При выборе голоса из библиотеки подбирай его под ПОЛ И ТОН персоны (см. шаг
7 «Кто персонаж?») — не только женские голоса; если персонаж — мужчина,
предлагай мужские.

Команда упала с `401` и телом вида `"missing_permissions"`/
`"message": "...missing the permission voices_read..."` — ключ рабочий, но
у него ограниченная область действия (ElevenLabs позволяет создавать ключи
только с правом `text_to_speech`, без `voices_read`/`user_read` — обычная
практика для продакшен-ключей). Это НЕ повод останавливать setup: список
голосов — только вспомогательный шаг для выбора вслепую. Сообщи
пользователю причину (ключ без права на листинг голосов) и попроси
назвать `voice_id` напрямую (он виден в кабинете ElevenLabs у каждого
голоса) — сам `voice_id` для TTS-запросов права `voices_read` не требует
(проверится синтезом на первом ролике).

### Голос пользователя (клон ElevenLabs)

1. Спроси: «Озвучивать твоим голосом или готовым?» Если своим:
2. Попроси запись голоса 1–2 минуты **на выбранном языке**: чистая
   речь без музыки и шума, обычный разговорный темп (можно голосовым
   сообщением; форматы mp3/wav/m4a).
3. Запусти сам: `$env:ELEVENLABS_API_KEY="<ключ>"; .venv\Scripts\python.exe -m reels_factory clone-voice --audio <файл> --name "<имя пользователя>"`
4. `voice_id` из ответа запиши в `factory/config.yaml` одновременно в
   `voice_id` и `voices[language]`; запиши `voice_language: language`.
5. Про тарифы/лимиты ElevenLabs пользователю НЕ рассказывай — ключ наш
   (авторов продукта), это не его забота. Ошибка доступа/лимитов — сообщи
   пользователю нейтрально «настрою голос чуть позже, продолжаем» и передай
   проблему нам (Вася/Юля).

Не хочет клон — бери голос из библиотеки (см. выше, под пол/тон персоны).

Критерий: у тебя есть конкретный `voice_id`, подтверждённый пользователем
(через список ИЛИ названный им напрямую), `voice_language == language` и
`voices[language] == voice_id`.

## Шаг 7. Интервью: персонаж, тема, ниша, продукт

Формат уже спрошен на шаге 4 (нужен был раньше — определяет, нужен ли
HeyGen) — здесь его повторно НЕ переспрашивай, просто используй ответ.

### Кто персонаж? (`persona`)

Персонаж — тот, кто ВЕДЁТ ролик; под него движок пишет реплики сценария.
Собери `persona.description` (обязательно) и `persona.speech_style`
(опционально — манера речи). Предложи пользователю два варианта:

**(а) Вымышленный персонаж.** Пользователь описывает сам («девушка-бариста,
25 лет, дружелюбная»). Если он прислал фото аватара — можешь предложить
черновик описания по фото, а пользователь поправит. `speech_style` — по
желанию.

**(б) «Персонаж — это я».** Составь описание манеры речи владельца сам:
- если в текущей сессии/памяти уже есть достаточно его сообщений — набросай
  `speech_style` (короткие фразы? прямота? юмор? канцелярит?) по ним;
- если сессия свежая и примеров мало — попроси 3–4 образца его текстов
  (посты/сообщения) и составь черновик по ним;
- покажи черновик `description`/`speech_style` на подтверждение, правь по
  замечаниям. Фото — своё (шаг 5). Голос — предложи клон своего голоса (IVC,
  шаг 6) либо библиотечный под его пол/тон.

Критерий блока: есть непустой `persona.description`, при варианте «это я» —
подтверждённый пользователем черновик.

### Остальное интервью

Спроси у пользователя (по одному вопросу за раз, не вываливай всё списком):

1. **Тема** рилсов (`theme`) — про что ролики.
2. Как тема **звучит в речи** (`theme_spoken`), если отличается от
   написания (склонения/сокращения) — можно пропустить, тогда равно theme.
3. **Ниша/ключевики** (`niche_keywords`) — по чему искать виральные ролики
   на этапе research (несколько фраз).
4. **Продукт**: имя (`product.name`), легенда (`product.legend` — контекст
   для сценария, не пересказывается зрителю в лоб), CTA-фраза
   (`product.cta_phrase` — ДОСЛОВНО, она войдёт в реплику один в один),
   варианты написания бренда/терминов для субтитров
   (`product.brand_captions` — что мог услышать Whisper вместо каждого
   термина; формат — объект `отображение: [варианты]`, НЕ список).

Критерий: собраны все обязательные поля (theme, format, persona.description,
product.name, product.cta_phrase — как в `load_config`), плюс из шагов 5/6
`avatar.heygen_asset_id` (обязателен для `format: split` и `format: avatar`)
и `voice_id`; `voice_language` совпадает с `language`, а
`voices[language] == voice_id`.
