# Research

Ниже — инструкции ДЛЯ ТЕБЯ (Claude), не для пользователя: поиск, скачивание,
разметку и анализ выполняешь ты сам, пользователя спрашиваешь только когда
формулировка неоднозначна или порог отбора не набирается. Все шаги этого
скилла БЕСПЛАТНЫ (yt-dlp и faster-whisper — локально, без платных API) —
гейт «до трат» здесь ничего не блокирует, но общее правило «неоднозначно →
переспроси» всё равно действует.

Предусловие: `factory/config.yaml` существует (пройден `/reels-factory:setup`).
Если файла нет — останови и попроси сначала пройти `/reels-factory:setup`.

## Шаг 0. Прочитать конфиг

```powershell
.venv\Scripts\python.exe -c "from reels_factory.config import load_config; import json; c=load_config(); print(json.dumps({'theme':c['theme'],'theme_spoken':c.get('theme_spoken'),'niche_keywords':c.get('niche_keywords')}, ensure_ascii=False))"
```

Возьми `theme`, `theme_spoken`, `niche_keywords` — по ним пойдёт поиск.
Критерий: у тебя есть тема и хотя бы одна ключевая фраза ниши (если
`niche_keywords` пуст — используй саму `theme` как единственный запрос и
предупреди пользователя, что подбор будет грубее).

## Шаг 1. Пул кандидатов — yt-dlp ytsearch

TikTok сюда сам не ищешь — только если пользователь прислал ссылки (добавь
их в пул на шаге 4 наравне с находками YouTube; медиану канала для них
считать не обязательно, если yt-dlp не отдаёт метаданные канала — просто
отметь это ограничение в таблице).

На каждую фразу из `niche_keywords` (и на саму тему, если фраз мало):

```powershell
.venv\Scripts\yt-dlp.exe "ytsearch40:<ключевая фраза> shorts" --dump-json --no-warnings --skip-download >> work/research_pool.jsonl
```

`--dump-json` даёт по одной JSON-строке на видео: `id`, `webpage_url`,
`title`, `view_count`, `duration`, `upload_date` (YYYYMMDD), `channel_id`,
`channel_url`, `channel`. Собери строки в `work/research_pool.jsonl`, убери
дубли по `id`.

Шортс — обычно `duration` ≤ 60-180с; ytsearch-выдача может подмешать обычные
ролики — отфильтруй их по `duration` и по факту, что ролик лежит в разделе
`/shorts` канала (проверишь на шаге 2).

Критерий: в `work/research_pool.jsonl` есть уникальные кандидаты (без дублей
по `id`), у каждого — `view_count`, `duration`, `channel_id`/`channel_url`,
`upload_date`.

## Шаг 2. Медиана канала и множитель виральности

На каждый уникальный `channel_id`/`channel_url` из пула — последние ~20
шортсов этого канала:

```powershell
.venv\Scripts\yt-dlp.exe "<channel_url>/shorts" --dump-json --no-warnings --skip-download --playlist-end 20 >> work/channel_<id>.jsonl
```

Посчитай медиану `view_count` по этим ~20 роликам. На каждого кандидата из
пула:

```
множитель = view_count(кандидата) / медиана(его канала)
```

Отбор в выборку: множитель ≥5× И `upload_date` не старше 12 месяцев от
ФАКТИЧЕСКОЙ сегодняшней даты на момент запуска (сравнивай `upload_date` в
формате YYYYMMDD с реальным «сегодня», не подставляй дату из старых заметок).

Критерий: у каждого кандидата, прошедшего порог, посчитаны и записаны
`view_count`, медиана канала, множитель.

## Шаг 3. Отбор топ-15-20

Отсортируй прошедших порог по множителю по убыванию, возьми топ-15-20.

- Меньше 15 прошло порог → сначала расширь пул (новые формулировки
  `niche_keywords`, ещё раз шаг 1), а не понижай порог молча.
- Совсем мало кандидатов даже после расширения → предупреди пользователя и
  спроси явно: расширить нишу дальше или принять меньший порог (не решай
  за него молча).

Критерий: список из 15-20 роликов с множителем ≥5× зафиксирован — это и есть
будущая таблица «Ролики» в `factory/analysis-<тема>.md`.

## Шаг 4. Скачать отобранные

```powershell
.venv\Scripts\yt-dlp.exe "<url>" -f "bv*[height<=1080]+ba/b[height<=1080]/b" --merge-output-format mp4 --no-warnings -o "work/research/<n>/source.mp4"
```

(`<n>` — порядковый номер ролика в выборке.) Критерий: у каждого отобранного
ролика есть `work/research/<n>/source.mp4`.

## Шаг 5. Хук покадрово — контактный лист + транскрипция

**Контактный лист первых 1-3 секунд** (что на экране/в ушах в самом начале):

```powershell
ffmpeg -y -ss 0 -t 3 -i work/research/<n>/source.mp4 -vf "fps=6,scale=320:-1,tile=6x3" work/research/<n>/hook_contact.png
```

(если `ffmpeg` не найден в PATH этого вызова — возьми путь через
`.venv\Scripts\python.exe -c "from reels_factory.config import FFMPEG; print(FFMPEG)"`
и подставь его вместо `ffmpeg`.) Прочитай PNG инструментом чтения файлов —
опиши, что видно кадр за кадром, своими словами.

**Транскрипция** (дословный хук + опора для кейса/реплик):

```powershell
.venv\Scripts\python.exe -c "from reels_factory.transcribe import transcribe_file; import json; print(json.dumps(transcribe_file('work/research/<n>/source.mp4', 'work/research/<n>', model_size='small', language='ru'), ensure_ascii=False))"
```

Пишет `work/research/<n>/words.json` (слова с таймкодами). Слова с
`start<3` — дословный текст хука. Фраза неразборчива на `model_size='small'`
— перезапусти с `'medium'` или `'large-v3'` (медленнее, точнее).

## Шаг 6. Комментарии

```powershell
.venv\Scripts\yt-dlp.exe "<url>" --write-comments --dump-json --skip-download --no-warnings > work/research/<n>/meta_comments.json
```

Из поля `comments` возьми топ по `like_count`: цитаты «что зацепило»,
повторяющиеся вопросы/боли аудитории, реакция на конкретные приёмы. Для
TikTok, если yt-dlp не отдаёт комментарии — так и отметь, не выдумывай.

## Шаг 7. Разбор по канону → `factory/analysis-<тема>.md`

Файл уже скопирован из шаблона на этапе setup. Заполни по разделам шаблона
на каждый ролик: **сценарий/кейс** (о чём ролик), **хук + первые 3 секунды**
(дословно, из шага 5, + тип хука: fail_first/clutch_save/number_shock/
question_hook/before_after/insight_reveal/другое своими словами),
**харизма** (поведение, взгляд, эмоции, стиль речи), **подача** (темп,
монтаж/склейки, крупность плана, название под роликом как хук, обложка,
раскладка, сабы), **тайминги** (длина хука, частота склеек, момент пейоффа),
**комментарии** (из шага 6). Не пересказывай ролик целиком — фиксируй ВЫВОД.

Заполни таблицу «Паттерны»: КАЖДЫЙ паттерн — только с указанием, **на какую
метрику работает и почему** (удержание в первые 3с / досмотр до конца /
шеринг / комментарии + короткий механизм, не общие слова «работает хорошо»).

Критерий готовности: паттерны повторяются минимум в нескольких роликах
выборки (не единичный случай) — это и есть материал для гипотез.

## Шаг 8. Гипотезы-рецепты → `factory/hypotheses.md`

Тоже уже скопирован шаблоном. Свяжи 2-3 паттерна в РЕЦЕПТ (не однопеременная
гипотеза): «Если [паттерны], то [метрика], потому что [механизм]». Оцени
частоту/силу/вклад/стоимость и посчитай счёт:

```
счёт = (частота × сила × вклад_в_метрику) / стоимость
```

Отсортируй «Сводку» по убыванию счёта — верхний рецепт станет входом
`/reels-factory:script`.

Критерий: очередь рецептов в `factory/hypotheses.md` проранжирована, топ-1
рецепт явно выделяется.

## Общие правила
- Неоднозначная формулировка (порог отбора, спорный паттерн) — переспроси
  пользователя, не решай молча.
- Свои надписи на видеоряд НИКОГДА не добавляй — даже если у конкурентов в
  выборке был плашечный хук, фиксируй это как НАБЛЮДЕНИЕ в анализе, а не как
  приём для собственного видеоряда.
- Караоке-сабы в итоговом рилсе — только речь блогерши (это к сборке, но
  держи в уме при разборе чужой «подачи»).
- Всё пишешь на русском.

Итог этапа: `factory/analysis-<тема>.md` с повторяющимися паттернами и
`factory/hypotheses.md` с проранжированной очередью рецептов. Дальше —
`/reels-factory:script`.
