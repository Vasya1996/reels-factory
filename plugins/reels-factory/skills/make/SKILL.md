# Make

Инструкции ДЛЯ ТЕБЯ (Claude). Предусловие: пользователь уже сказал «ок» по
сценарию и раскадровке на `/reels-factory:script` — если этого не было в
текущем диалоге, ОСТАНОВИСЬ и попроси пройти `/reels-factory:script` (или
явное подтверждение) сначала: дальше в этом скилле — платные операции
(ElevenLabs TTS + HeyGen при `format: split`).

Запускай всё из корня рабочей папки проекта (там же `factory/`, `work/`,
`.venv/`). Ключи `HEYGEN_API_KEY`/`ELEVENLABS_API_KEY` должны быть в env
(сохранены на `/reels-factory:setup`, User-scope переменные подхватываются
новыми процессами автоматически); если команда упадёт с 401/403 — подставь
ключ явно в ТОМ ЖЕ вызове (`$env:HEYGEN_API_KEY="..."; ...`) и порекомендуй
пользователю перепройти шаг 4 `/reels-factory:setup`.

## Шаг 1. Видеоряд (broll)

Источник — по плану из `work/<имя>/storyboard.md` (ролик из research или
новый) или файл пользователя.

Критерии выбора: чистый звук БЕЗ чужого голоса (звук видеоряда идёт в микс
финального рилса постоянным фоновым слоем `volume=0.6` поверх голоса
ведущего — чужой голос будет слышен и собьёт с толку); авторские права —
предпочитай ролики с разрешённым реюзом (Creative Commons/явное разрешение/
свои материалы пользователя); нет уверенности в правах — предупреди
пользователя явно, не решай молча.

```powershell
.venv\Scripts\yt-dlp.exe "<url>" -f "bv*[height<=1080]+ba/b[height<=1080]/b" --merge-output-format mp4 --no-warnings -o "work/<имя>/broll_source.mp4"
```

(или прими локальный файл от пользователя напрямую — путь к нему и есть
источник).

## Шаг 2. Контактные листы — разметка моментов

На каждую роль блока (`hook`/`development`/`payoff`/`cta`, и `context`, если
сценарий 5-блочный — см. `work/<имя>/scenario.json`) найди подходящий момент
в исходнике. Для `context` — либо разметь свой момент (запись в `segments`
шага 3), либо осознанно оставь без записи, чтобы он продолжил отрезок `hook`
по правилу «роль без записи продолжает предыдущий отрезок» (см. шаг 3) — это
осознанный выбор, а не пропуск по недосмотру. Скани окно контактным листом:

```powershell
ffmpeg -y -ss <начало окна> -t 120 -i work/<имя>/broll_source.mp4 -vf "fps=1,scale=320:-1,tile=8x8" work/<имя>/contact_<окно>.png
```

(`fps=1` → один кадр в секунду, `tile=8x8` = 64 кадра = 64 секунды исходника
на листе; номер кадра в сетке = смещение в секундах от `-ss`.) Прочитай PNG
инструментом чтения файлов — смотри кадры сам, не гадай. Уточни точный
момент прицельным кадром:

```powershell
ffmpeg -y -ss <кандидат-секунда> -i work/<имя>/broll_source.mp4 -frames:v 1 work/<имя>/check.png
```

(если `ffmpeg` не в PATH этого вызова — путь через
`.venv\Scripts\python.exe -c "from reels_factory.config import FFMPEG; print(FFMPEG)"`.)

## Шаг 3. `broll_plan.json`

```json
{
  "segments": [
    {"role": "hook", "offset": 12.4},
    {"role": "development", "offset": 40.0},
    {"role": "payoff", "offset": 58.0, "slow": {"at": 1.0, "dur": 1.5, "factor": 0.5}},
    {"role": "cta", "offset": 70.0}
  ],
  "punch": [[16.5, 0.5]],
  "facts": {
    "hook": "только то, что реально видно на контактном листе роли hook",
    "development": "...",
    "payoff": "...",
    "cta": "..."
  }
}
```

`segments` — по одной записи на роль, где начинается НОВЫЙ отрезок исходника
(`offset` в секундах); роль без записи продолжает предыдущий отрезок. `slow`
опционален — под-окно `{at, dur, factor}` внутри блока замедляется. `facts`
— соседний ключ в том же файле (движком игнорируется, читается только тобой
на шаге 4) — по каждой роли только то, что РЕАЛЬНО видно на контактном
листе, без домыслов.

`punch` — опционален, список окон `[start_s, dur_s]` В ТАЙМЛАЙНЕ РИЛСА (после
ретайминга, не исходника broll) — лёгкий наезд-зум на килл/пик/вау-моменте.
Ставь 1-2 окна по 0.5-0.6с максимум на самый сильный момент ролика (обычно
внутри `development`/`payoff`) — не на каждую реплику, иначе эффект теряет
силу. Свуш на переходах добавляется на эти окна АВТОМАТИЧЕСКИ (движок сам
включает точки `punch` в `whoosh_at`, когда `whoosh_at` не задан явно) — не
нужно прописывать whoosh отдельно.

**Формат `avatar` — ВСТАВКИ.** У сегмента добавь `"insert": true` — тогда
видеоряд этого блока рисуется ПОВЕРХ аватара фуллскрин в окне блока (по
раскадровке из `/reels-factory:script`), а не низовым слоем. Звук вставки
подмешивается только в её окне (`volume=0.6`), на границах — свуш. Обычные
сегменты без `insert` в формате `avatar` игнорируются. 1–3 вставки по 2–5с —
не в каждый блок. Если вставок нет вовсе — `broll_plan`/`--broll` можно не
давать совсем (аватар соберётся с одним голосом). Пример вставки в
`development`:

```json
{"segments": [{"role": "development", "offset": 40.0, "insert": true}]}
```

Сохрани в `work/<имя>/broll_plan.json`.

## Шаг 4. ГЕЙТ ПРАВДЫ (до сборки — пока бесплатно)

Сверь `speech` каждого блока `work/<имя>/scenario.json` с `facts` из шага 3
и с самими кадрами: каждое утверждение в репликах (особенно `development`/
`payoff` — кейс, результат) должно подтверждаться тем, что реально видно
под этим блоком. Несовпадение = СТОП, не запускай сборку:
- дело в видеоряде — подбери другой offset/источник (шаги 1-3 заново);
- дело в реплике — вернись на `/reels-factory:script` и поправь текст (это
  бесплатно, дешевле, чем переделывать после платной сборки).

## Шаг 5. Сборка

```powershell
$env:PYTHONUTF8="1"; .venv\Scripts\python.exe -m reels_factory make --workdir <имя> --broll work/<имя>/broll_source.mp4 --broll-plan work/<имя>/broll_plan.json
```

(`PYTHONUTF8=1` — иначе русский текст в JSON-выводе (например причина
провала гейта) в stdout PowerShell читается абракадаброй.)

Для формата `avatar` БЕЗ вставок `--broll`/`--broll-plan` можно опустить
(`... make --workdir <имя>`) — аватар соберётся с одним голосом. Со вставками
`--broll` обязателен (источник видеоряда для вставок).

Может идти долго (HeyGen рендерит аватар-фрагменты по одному блоку с
поллингом до 10 минут на блок при `format: split` и `format: avatar`) — если
запускаешь в фоне, ДОЖИДАЙСЯ завершения, не убивай процесс раньше времени.

Коды выхода: `0` — всё собралось, QA пройден; `1` — жёсткий сбой стадии (см.
поля `stage`/`error` в JSON-ответе — разбирайся по
`superpowers:systematic-debugging`, не гадай); `2` — сборка прошла, но
провалился хотя бы один QA-гейт (`qa_pass: false`, смотри `gates`).

**Известные грабли:** если фоновая сборка была всё же прервана — скачанный
видеоряд (`broll_source.mp4`) и CTA-фрагмент аватара (кэш в
`work/avatar_cache` по sha1 голоса+аватара) переиспользуются автоматически
при повторном `make`; а вот голос (ElevenLabs) и аватар-фрагменты
hook/development/payoff (HeyGen) — НЕТ, полный повтор `make` оплатит их
заново. Поэтому лучше дождаться завершения, чем перезапускать вслепую.

## Шаг 6. Разбор гейтов

- **D1_duration** — фактическая длительность далеко от ретаймленной
  ожидаемой — TTS вернул реплику заметно длиннее/короче номинала, обычно
  смиряться, если в пределах 14-40с.
- **D2_resolution** — не 1080×1920@30 — проблема кодирования, проверь ffmpeg.
- **D3_loudness** — LUFS вне -14±1.5 — двухпроходный loudnorm должен был
  попасть сам, FAIL значит апстрим-проблема со звуком, копай.
- **D4_captions** — `caps.ass` не создался — ошибка на стадии субтитров.
- **D5_voice** — голос ведущего не слышен в окне хука — проверь громкость
  TTS/микса.
- **D6_broll_bed** — слой видеоряда пропал в паузе после хука — проверь
  выбранный offset (может, там тишина/обрыв клипа). Для формата `avatar`:
  `SKIP`, если вставок нет (это норма); если есть — замер в окне первой
  вставки, FAIL значит звук вставки не подмешался.
- **D7_captions FAIL** — в сабах проскочил ИЗВЕСТНЫЙ коверканный вариант
  бренда/темы — добавь недостающий вариант в `product.brand_captions`/
  `theme_captions` в `factory/config.yaml` и пересобери.
- **D7_captions warn-список** — подозрения по Левенштейну, НЕ блокирует.
  Разбери каждое слово вручную (глазами по кадру/на слух): реально
  спутанный бренд/тема — добавь в конфиг; похожее по звучанию, но
  постороннее слово — оставь как есть, не добавляй в конфиг вслепую.

## Шаг 7. Гейт правды — повторно на готовом mp4

Тайминги после ретайминга/панчей могут сдвинуться против плана. Прогляди
готовый `work/<имя>/reel.mp4` в ключевых точках (те же утверждения, что на
шаге 4) — подтверди, что видеоряд под репликой всё ещё соответствует
сказанному. Расхождение — не отдавай пользователю молча, предупреди.

## Шаг 8. Выдача пользователю

- `work/<имя>/reel.mp4`;
- `title` из `work/<имя>/scenario.timed.json` (или `scenario.json`) —
  метаданные для публикации (заголовок/подпись поста), НЕ выжжен в кадр;
- список «что проверить на слух»: дословность и естественность CTA-фразы,
  ударения из шага 4 `/reels-factory:script`, все слова из D7-warn.

## Общие правила
- Неоднозначно (права на видеоряд, трактовка гейта) — переспроси ДО траты
  (шаг 5 — единственный платный шаг всего цикла, до него всё ещё можно
  остановиться бесплатно).
- Свои надписи на видеоряд НИКОГДА не добавляй.
- Сабы — только речь ведущего (движок это и делает технически — voice.wav
  без слоя видеоряда).
- Всё на русском.

Итог этапа: mp4 + title + список проверки на слух. Дальше — публикация
пользователем и `/reels-factory:review` после того, как накопятся метрики.
