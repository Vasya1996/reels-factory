## Модуль A. Storyboard Compiler (script → tz)

**Задача:** превратить сценарий в раскладку сегментов с эффектами, как это делает монтажёр.

**Вход:**
- `words.json` — слова с таймкодами (Whisper/ElevenLabs), уже есть
- `script.json` — текст + при желании `visual_note` на блок (из Agent 2 WRITER)
- `config` — бренд (цвет, шрифт, вотермарк), список доступных эффектов, доступность b-roll

**Процесс:**
1. **Сегментация на фразы** — по паузам (>250мс) и пунктуации. Уже реализовано (`buildChunks` логика).
2. **LLM-раскладка (Claude).** На каждую фразу назначить: `effect`, `camera` (тип зума), `transition_in`, роль подписи (`bottom/top/hidden`), ключевые слова. Промпт содержит:
   - каталог эффектов (ниже) и жёсткие правила (ниже),
   - тон/архетип ролика (хук → польза → CTA),
   - требование ротации: соседние эффекты не повторяются, каждый тип зума ≤1 раз.
3. **Извлечение keywords** — 5-8 смысловых слов для подсветки в подписях.
4. **Вывод** — валидный `tz_reels_v6.json` по нашей схеме.

**Каталог эффектов (то, что умеет движок сейчас):**
- `none` — говорящая голова (аватар в кадре)
- `broll` со `style`: `pip` (картинка-в-картинке), `split` (сплит-скрин), `fullscreen`, `background+particles`
- `emoji_pop_sequence` — Fluent 3D эмодзи по словам
- `chart_bars` — инфографика-бары на тёмной подложке
- `avatar_bubble` — вебка-кружок/квадрат (`shape: circle|square`), с face-детекцией
- `cta_endcard` — кнопка подписки

Зумы (каждый ≤1 раз за ролик): `zoom_out, punch, push, snap_zoom, ken_burns, pulse, shake_zoom`.
Переходы (≤2 типа за ролик): `whip, zoom_blur, flash`.

**Промпт-контракт (упрощённо):**
```
System: Ты монтажёр коротких видео. На вход — фразы с таймкодами.
Верни JSON строго по схеме tz. Соблюдай ПРАВИЛА (список). Эффекты не повторяй
подряд, каждый зум используй не больше раза, b-roll-стили чередуй.
User: { phrases:[{i,start,end,text}], brand:{...}, effects_catalog:[...], broll_available:N }
Output: { segments:[...], captions:{keywords:[...]} }
```

## Модуль B. B-roll Library + семантический подбор

**Задача:** под каждую фразу, где нужен b-roll, автоматически достать релевантный клип из библиотеки (чинит боль «всего 2 клипа / повторы»).

**Библиотека:** `broll_library/` — клипы + `index.json` с метаданными:
```json
{ "clip_042.mp4": {
    "caption": "руки печатают на клавиатуре, блокнот с заметками",
    "tags": ["работа","клавиатура","заметки"],
    "embedding": [0.01, -0.23, ...],   // 512-мерный вектор
    "duration": 12.2, "res": [1080,1920] } }
```

**Индексация (разово при добавлении клипов):**
1. Из каждого клипа берём 3-5 кадров (равномерно).
2. VLM (Claude vision или BLIP) генерит короткое описание клипа → `caption` + `tags`.
3. CLIP/ImageBind считает эмбеддинг (усреднённый по кадрам) → `embedding`.
4. Пишем в `index.json`.

**Подбор (на каждую b-roll-фразу):**
1. Строим запрос из текста фразы (+ `visual_note`, если есть).
2. Эмбеддим запрос тем же CLIP (текстовый энкодер).
3. Косинусная близость к клипам → top-k.
4. **Дедуп:** не берём клип, уже использованный в этом ролике.
5. Порог: если лучший score < 0.24 → фолбэк (генерация Runway/Kling ИЛИ нейтральный клип), логируем «слабое совпадение».
6. Проставляем `src` и `offset` в соответствующий сегмент tz.

**Стек:** `open_clip` (ViT-B/32, CPU-ок) для эмбеддингов, наши кадры через ffmpeg. ImageBind опционально (если захотим искать ещё и по звуку). Всё локально, без тяжёлого фреймворка.

## Обновлённая схема tz (v6) — что добавилось

```json
{
  "meta": {...},
  "brand": {...},
  "captions": { "base_style": "accumulate", "font": "Unbounded", "keywords": [...] },
  "segments": [
    {
      "id": 4, "start": 8.16, "end": 10.88, "phrase": "...",
      "camera": { "type": "ken_burns" },
      "transition_in": "none",
      "effect": {
        "type": "broll", "style": "pip",
        "broll_query": "нейросеть запоминает инструкции, ноутбук",   // ← НОВОЕ: запрос для Модуля B
        "src": null,        // ← заполняет Модуль B после retrieval
        "offset": 0
      },
      "caption": "top"
    }
  ]
}
```
Ключевое новшество: Модуль A пишет `broll_query` (что нужно показать), Модуль B заполняет `src`. Раскладка и подбор материала разделены.

## Валидатор ТЗ (линтер монтажных правил)

Автопроверка сгенерированного tz перед рендером. Все правила, что мы уже зашили в движок, дублируются как проверки на этапе плана:
- **Флеш-кадры:** нет плана < `MIN_SHOT` (1.2с), зажатого между двумя другими. Соседние перекрывающие сегменты (fullscreen/particles/chart) с зазором < 1.2с → помечаются под общий бэкплейт.
- **Границы подписей:** чанк субтитров не пересекает границу сегмента.
- **Зумы:** каждый тип зума ≤1 раз.
- **Эффекты:** соседние сегменты не одного типа; b-roll-стили чередуются.
- **Подложка:** любой полноэкранный оверлей поверх лица → обязателен бэкплейт.
- **B-roll:** каждый `src` заполнен и клип не короче нужного окна; нет повторов клипа.
- **Бренд:** ≤5 хештегов, без длинного тире, вотермарк включён.

Нарушения → автofix (продлить оверлей / сдвинуть) или флаг в лог с предложением.

## Как встраивается в общий конвейер (ARCHITECTURE.md)

```
Agent 2 WRITER  → script.json (+ visual_note)
Agent 3 VOICE   → voiceover.mp3 + words.json
Agent 5 EDITOR:
   ├─ Модуль A (Storyboard Compiler)  → tz_v6 черновик
   ├─ Модуль B (B-roll Retrieval)     → tz_v6 с src
   ├─ Валидатор                        → tz_v6 финал
   └─ Revideo render                   → reel.mp4
Agent 6 PUBLISHER → публикация
```
Оба модуля — детерминированные шаги внутри Agent 5, вызываются последовательно. Ручной правки tz больше не требуется (но можно вмешаться на любом шаге).
