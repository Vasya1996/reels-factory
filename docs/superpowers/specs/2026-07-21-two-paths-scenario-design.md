# Дизайн: два пути сценария + хуманизация (зона Васи)

Дата: 2026-07-21. Статус: на ревью у Васи (v2 — после ресёрча субагентов).

## Зачем

Две продажи, два типа клиентов:
- **Серик** — «вот мой текст, скажи его за меня». Текст его, менять нельзя.
- **Жанна** — «вот сырьё (транскрибация встречи), сама придумай и напиши». Текст пишем мы.

Общая цель: связный сценарий + человечная устная подача, на русском и казахском.

## Граница зон

Выход Васи = `scenario.json` (текст с разбивкой по блокам) + аудио ElevenLabs
(файлы или ссылки). Всё дальше (аватар, перебивки, монтаж, субтитры) — зона Юли.
Юля сама решает, как делать перебивки; якоря «где о чём говорит» ей не передаём.
`ingest.py`, `compose.py`, `render.py`, `captions.py` не трогаем.

## Путь 1 — «Дословно» (Серик)

1. Вход: готовый текст или голосовое (расшифровка локальным Whisper, бесплатно).
2. Правок смысла — ноль. Единственная операция: хуманизатор в режиме
   «только фонетика» — разрешена одна операция: фонетическая запись терминов,
   брендов, фамилий и иностранных слов («Microsoft» → «Майкрософт»,
   «UGC» → «ю-джи-си») и числа/валюты прописью, как требует сама ElevenLabs.
   Всё остальное трогать запрещено. Список замен показывается пользователю.
3. Никакого CTA от движка — ни слова сверх текста пользователя.
4. Проверок длины нет (длинные рилсы тоже залетают). В чат — информационная
   строка «~N слов ≈ M сек, озвучка+аватар ≈ $X» (прайс по актуальной модели
   HeyGen, которую подтвердит Юля). Строка живёт только в чате: в сценарий и в
   ElevenLabs не попадает.
5. Разбивка по блокам — только как формат передачи Юле: границы кусков,
   текст не меняется ни на букву.
6. «Ок» пользователя (для казахского — «ок» самого носителя, т.е. Серика)
   ДО первого платного шага. Потом озвучка ElevenLabs → передача Юле.

## Путь 2 — «Из сырья» (Жанна)

1. Вход: текст или аудио (аудио расшифровываем локально).
2. Скилл извлечения идей (№0 ниже): 2–3 идеи с обоснованием и предлагаемой
   длиной. Любое слово пользователя («короче», «сделай минуту») переопределяет.
3. Пользователь выбирает идею → движок конвейером:
   - **генерация** (скилл №1): цитаты из сырья, язык, длина;
   - **хуманизатор** (скилл №2, режим «полировка»);
   - **судья** (скилл №3): годен / не годен + претензии; не годен → автоповтор:
     редактор получает текст и претензии, до 2 кругов; на повторном круге судья
     получает список прошлых претензий — проверить, что устранены, плюс полная
     переоценка;
   - **проверка целостности**: файл создался, в каждом блоке непустой текст,
     блоки по порядку; если у пользователя зафиксирована своя CTA-фраза —
     она вошла дословно. Механика, не качество.
4. CTA включён по умолчанию и ГЕНЕРИРУЕТСЯ как часть сценария под цель ролика
   (заявки) — никакой настройки заранее. Судья проверяет, что призыв есть.
   Сказал пользователь «призыв всегда делай таким» — фраза запоминается как
   умолчание, меняется словами в чате. Пользователь файлы не редактирует.
5. Показ реплик → «ок» → озвучка → передача Юле.

Как плагин выбирает путь: по запросу в чате («озвучь этот текст» → путь 1;
«сделай ролик из этой встречи» → путь 2); при двусмысленности — один вопрос.
Движку режим передаётся параметром.

## Оформление: инструкции = скиллы плагина (итог ресёрча)

Все четыре инструкции оформляются как полноценные скиллы плагина по
официальным практикам Anthropic, а не как промпты в коде движка:

- frontmatter `disable-model-invocation: true` — скилл не всплывает в чате и
  не ест контекст, вызывается только явно;
- движок вызывает их детерминированно: `claude -p "/reels-factory:<имя> <путь>"
  --plugin-dir ...` — официально задокументированный механизм; выход
  фиксируется `--json-schema` (гарантированная структура вместо парсинга);
- контекст (транскрипт, гипотеза) передаётся файлом в work-папке, аргумент —
  путь к нему;
- справочники и рубрики — в `references/` скилла (progressive disclosure:
  грузятся только когда нужны);
- текст инструкций лежит в файлах скилла, движок при необходимости может
  читать их напрямую — переход на прямой API в будущем не потребует переписывания;
- каждый скилл создаётся и тестируется через официальный skill-creator:
  2–3 eval-кейса в `evals/evals.json`, прогон с/без скилла, A/B перед правками;
- существующие чат-скиллы плагина (script, make...) остаются, script начнёт
  ссылаться на те же файлы.

Скиллы: `extracting-ideas` (№0), `writing-scenario` (№1), `humanizing-speech`
(№2, один скилл с режимами polish|phonetics аргументом), `judging-script` (№3).

В `llm.py` добавляется `--plugin-dir` и `--json-schema` в вызов `claude -p`.

## Валидатор

Старый набор правил (длительность 14–40с, тема в первых фразах, хук без
бренда и т.д.) упраздняется как гейт. Остаётся целостность + дословный CTA
(только если зафиксирована фраза, только путь 2). Всё качество — судья.
Попутно чинится баг: валидатор валит сценарий при латинском названии темы
(`scenario.py:258`).

## Языки

Язык (`ru`/`kk`) прошивается насквозь: идеи, генерация, хуманизатор, рубрика
судьи, расшифровка аудио, озвучка. Сейчас `ru` захардкожен в `compose.py`
(Юлино) и `transcribe.py` (моё). Для казахского готовых списков ИИ-клише нет —
выводим свои по тому же методу и калибруем на обратной связи Серика.

## Черновики скиллов (v2, по итогам ресёрча)

### №0. `extracting-ideas` — извлечение идей из сырья

Роль: виральный продюсер соцсетей. Процесс:
1. Просканировать транскрипт по таксономии виральных моментов: спорное/смелое
   мнение, удивительный факт, эмоция (смех, признание, уязвимость), конкретный
   совет «вот как», яркая цитата, начало истории с интригой. Набрать 5–8
   кандидатов, только потом сужать.
2. Каждого кандидата оценить по взвешенной рубрике (источник — claude-shorts,
   индустриальный аналог — OpusClip Virality Score):
   Хук 30% / Понятность без контекста 25% / Эмоция 20% / Плотность пользы 15% /
   Развязка 10%. Порог отсечения 60/100. Балл — приоритизация для теста,
   не приговор (даже OpusClip не гарантирует).
3. Жёсткий фильтр «понятно без контекста встречи»: требует знания контекста —
   отклонить или переформулировать.
4. Выход (JSON): 2–3 идеи, у каждой — формулировка одной фразой, целевая
   эмоция зрителя, черновой хук, цитаты-опоры из транскрипта (защита от
   выдумывания), предлагаемая длина ролика с обоснованием.
5. Если есть `factory/analysis-*.md` / `hypotheses.md` (этап research) —
   сверять идеи с рецептами оттуда.

### №1. `writing-scenario` — генерация сценария

Ключевые правила (источники: ai-business-skills/script-video-global, OpusClip,
Kallaway, ElevenLabs):
1. Тайминг процентами — масштабируется на любую длину: хук 10% → проблема/
   история 25% → суть 30% → доказательство 25% → CTA 10%.
2. Хук: написать 2–3 варианта по формулам (конкретное число, контрарное
   утверждение, личная трансформация, исповедь, вопрос-вакуум, результат-вперёд,
   прогноз), выбрать по трёхшаговому тесту Kallaway: тема мгновенно ясна +
   контрастное слово/поворот + неожиданный сдвиг. Первые ≤12 произносимых слов
   должны содержать крючок. Запрещены приветствия и само-представления.
3. Одна идея на ролик, максимум 2 ключевых пункта, предложения ≤15 слов,
   писать как говорят.
4. Факты — только из цитат пользователя; каждое утверждение трассируется к
   источнику; ничего не выдумывать.
5. Под озвучку: числа/валюты/даты прописью, аббревиатуры как произносятся,
   термины и бренды транслитом, паузы пунктуацией, эмоция самим текстом
   (+ теги ElevenLabs где уместно).
6. CTA: один, в конце, под заявки, связан с темой; если пользователь
   зафиксировал фразу — дословно её.
7. Финальный самочек-лист + два адверсариальных прохода: «Скроллер»
   (остановит ли первая фраза?) и «Скептик» (не звучит ли как реклама/ИИ?).
   Переписывать до прохождения, потом отдавать.

### №2. `humanizing-speech` — хуманизация (режимы polish | phonetics)

База — три источника, собранные в один скилл:
1. **Русский справочник банов** — на основе humanizer-ru (MIT, 54 маркера в
   12 группах, «жёсткие баны»: «Не просто X, а Y», «в современном мире»,
   «данный», «является», «стоит отметить»...) + русская Википедия «Признаки
   сгенерированности текста» (раздувание значимости, рекламный язык,
   дидактика, размытые атрибуции, артефакты чатбота). НЕ перевод английского
   справочника — родные русские списки.
2. **Процесс из blader/humanizer**: калибровка голоса по образцу речи спикера
   (если есть его прошлые ролики/тексты); флаговать кластеры признаков, а не
   единичные маркеры + список «что НЕ трогать» (ложные срабатывания); список
   человеческих черт, которые НАДО сохранять (конкретные детали, смешанные
   чувства, вариативность длины фраз); диагностический проход «что здесь всё
   ещё от ИИ?» перед финалом.
3. **Слой «под озвучку»** (ElevenLabs best practices + правила Васи):
   короткие фразы, без сложносочинённых и причастных цепочек, без слов с
   кластерами п-б-м, термины/бренды/фамилии фонетически, числа прописью,
   ударения акутом в сложных словах, финальный тест — прочитать вслух.
4. **Факт-замок** (из humanizer-ru): числа, имена, факты при переписывании
   неприкосновенны.

Режимы (аргумент вызова, выбирается путём, не пользователем):
- `polish` (путь 2): переписывать формулировки свободно, факты — нет;
- `phonetics` (путь 1): только фонетика/числа прописью, больше ничего;
  вернуть список замен.

### №3. `judging-script` — судья

Принципы (Hamel Husain, arXiv-обзоры, Anthropic evaluator-optimizer):
бинарные критерии вместо шкал; рассуждение ДО вердикта; роль — «придирчивый
редактор, нанятый заказчиком; не знаешь, кто автор; при сомнении — брак»
(гасит мягкость и само-предпочтение судьи); якорные примеры pass/fail для
самых субъективных критериев (hook, speakable) прямо в промпте.

Критерии — бинарные, pass только при всех «да»:
1. **hook** — первые ≤12 слов содержат разрыв шаблона, петлю любопытства или
   конкретную цифру; нет приветствий и само-представлений.
2. **one_idea** — текст пересказывается одним предложением; нет второй темы.
3. **speakable** — читается вслух без запинки: нет фраз >15 слов без паузы,
   латиницы, аббревиатур без расшифровки, непроизносимых цифр, канцелярита;
   для казахского — естественный порядок слов, не калька с русского.
4. **facts** — числа, имена, утверждения совпадают с входом; не додумано.
5. **cta** — призыв есть, один, в конце, под заявки (только путь 2).
6. **fit_length** — текст соответствует длине, выбранной пользователем с идеей
   (~2.5 слова/сек). Не глобальный лимит — сверка с заказом.

Вердикт (JSON): `{"pass": bool, "scores": {...}, "issues": [{"criterion",
"where" (точная цитата ≤15 слов), "what" (в чём брак, одним предложением),
"fix" (исполняемая инструкция редактору, по возможности готовый вариант)}]}`.
Каждый fail-критерий — минимум одна претензия. Претензии = вход авторетрая.
Калибровка: 10–20 размеченных вручную сценариев до согласия с человеком >90%.

## Порядок работ

0. Скелет скиллов через skill-creator (структура, evals) — по ходу шагов 1–3.
1. Путь 1 «Дословно» целиком (Серик заплатил и ждёт; не зависит от остального).
2. Хуманизатор + судья.
3. Путь 2 «Из сырья» (реальная проверка на транскрибации Жанны).
4. Казахский насквозь.

Каждый шаг: автотесты (`pytest`, LLM подменяется заглушками; для скиллов —
evals через skill-creator), ветка `feat/vasya-...`, показ диффа простыми
словами, PR только после «ок».

## Решения, принятые в обсуждении 2026-07-21

- Текст Серика свят; исключение — фонетика/числа прописью узким режимом
  хуманизатора (LLM, не программный костыль).
- Проверок длины нет нигде; стоимость — информационная строка в чате.
- Идеи из сырья: 5–8 кандидатов → рубрика → 2–3 лучших с обоснованием →
  выбор пользователя. Длина — свойство идеи, переопределяется словами.
- Хуманизатор — гарантированный шаг движка; режим определяется путём.
- Качество проверяет LLM-судья по бинарной рубрике; код — только целостность.
- CTA: путь 1 — никогда; путь 2 — генерируется по умолчанию, фраза
  запоминается по слову пользователя. Никаких файлов настроек для пользователя.
- Инструкции — скиллы плагина (disable-model-invocation), создаются через
  skill-creator, вызываются движком через `claude -p /reels-factory:<имя>`.
- Пользователь не редактирует никакие файлы и справочники.
