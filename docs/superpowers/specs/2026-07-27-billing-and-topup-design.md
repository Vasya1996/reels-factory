# Биллинг и пополнение баланса — дизайн

Дата: 2026-07-27. Статус: согласовано с Васей в интервью 2026-07-25…27.

## Задача

Считать себестоимость каждого рилса по каждому провайдеру отдельно, списывать её
с наценкой из виртуального баланса пользователя, не пускать в платный рендер при
нехватке средств, и принимать пополнение через Tribute без ручного участия.

## Решения (приняты пользователем, не переспрашивать)

| Вопрос | Решение |
|---|---|
| Тип баланса | Виртуальный, в долларах, в нашей БД. Реальные деньги провайдерам платит Вася напрямую. |
| Наценка | 100% (множитель 2.0), в конфиге |
| Стоимость Клода | Включать в списание уже сегодня, по ценам API, хотя реально платится подписка |
| Нехватка баланса | Блокировать ДО первого платного шага, по оценке из утверждённого сценария |
| Провал по нашей вине | Наши издержки, не пользователя. Механика — возврат списанного на баланс, но **реализуется отдельной задачей после оплаты** (решение Васи 2026-07-27): `LedgerStore.refund_job` готов и покрыт тестами, вызывать его пока некому |
| Стартовый бесплатный баланс | Не нужен |
| Пополнение | Tribute, готовые инфопродукты (7 штук, USD и RUB), вебхук `new_digital_product` |
| Инструменты биллинга | Своя таблица в SQLite; Lago/OpenMeter избыточны на этом масштабе |

## Ставки (проверено роем субагентов 2026-07-26)

- HeyGen Photo Avatar (`type: "image"`, ветка бота) — **$0.05/сек**
- HeyGen Digital Twin (`look_id` задан) — **$0.0667/сек**
- ElevenLabs pay-as-you-go Multilingual v2/v3 — **$0.10 / 1000 символов**
- Claude — по моделям; фактическая стоимость берётся из `--output-format json`

Ставки живут в `factory/config.yaml`, обновляются руками. Автообновления нет
(для Клода существует библиотека `genai-prices`, но вводить зависимость ради
одной цифры избыточно — решение отложено).

## Архитектура

```
ПРОЦЕСС БОТА
  bot.py ──оценка до рендера──▶ estimate_micro() ──▶ хватает? ──нет──▶ экран пополнения
     │                                                  │да
     ▼                                                  ▼
  jobs (очередь в SQLite) ────────────────▶ subprocess: python -m reels_factory make
     ▲                                                  │
     │ чек по журналу после выдачи                      │
     │                                                  ▼
     │                                   ПРОЦЕСС СБОРКИ
     │                                     __main__._cmd_make ──▶ JobMeter
     │                                              │
     │                                     pipeline.run_make ──▶ платные шаги
     │                                              │
     └──────── work/billing.sqlite3 ◀───── billing.charge() на каждом шаге
                      ▲
  Tribute ──вебхук──▶ Caddy (tribute.<ip>.sslip.io) ──▶ localhost:PORT ──▶ credit()
```

**Границу процессов держать в голове:** бот не вызывает `run_make` — он
запускает `python -m reels_factory make` отдельным процессом (`bot.run_build`).
Поэтому объект учёта создаётся внутри процесса сборки и берёт `chat_id`/`job_id`
из `job.input.json`, а связывает процессы общий файл базы: WAL плюс
`busy_timeout` плюс идемпотентный `entry_id`.

### Хранилище

`work/billing.sqlite3`, тем же паттерном что `work/jobs.sqlite3` (WAL,
connection-per-call, `BEGIN IMMEDIATE` для атомарности).

Все деньги — **целые микродоллары** (1 USD = 1_000_000). Float для денег не
использовать: токены Клода дают суммы вида $0.000003, в центах они схлопнутся в
ноль, а float накопит дрейф.

Три таблицы:
- `balances(chat_id PK, balance_micro, updated_at)`
- `spend_log(entry_id PK, chat_id, job_id, provider, unit, quantity, unit_price_micro, cost_micro, charged_micro, refunded_at, created_at, meta_json)` — `refunded_at` заведена сразу, хотя возврат отложен: добавлять колонку потом означало бы миграцию базы с живыми балансами
- `topups(purchase_id PK, chat_id, amount_minor, currency, credited_micro, created_at, raw_json)`

`entry_id` — детерминированный ключ (`job_id:provider:step`), чтобы повтор шага
не списал дважды. `purchase_id` из Tribute — ключ идемпотентности пополнения
(вебхуки ретраятся сутки).

### Точки учёта

| Провайдер | Процесс | Где | Количество |
|---|---|---|---|
| HeyGen | сборки | `pipeline.run_make`, ветка по блокам | секунды готового mp4 (`render.media_dur`); кэш и локальные вставки — 0 |
| ElevenLabs | сборки | `tts.synth_voice`, после `raise_for_status` | `len(text)` |
| Claude | **бота** | `bot._charge_claude` после каждого из трёх `step_*` | сумма `total_cost_usd` по всем вызовам runner |

Клод стоит особняком: скиллы работают при подготовке сценария, то есть в процессе
бота и до появления сборки. Поэтому его траты пишутся с `job_id = None` и в чек по
ролику не попадают — они списываются раньше и не зависят от того, дойдёт ли
человек до сборки.

Клонирование голоса ElevenLabs не тарифицируется: это слот в тарифе, а не
расход за вызов. Ветка `avatar islands` не тарифицируется и закрыта
предохранителем — см. «Отложено» в плане.

### Переключение Клода на JSON

`ClaudeSkillRunner.run_skill` сейчас зовёт `--output-format text` и возвращает
`stdout` целиком. Меняем на `json`, парсим объект, **возвращаем поле `result`**
(контракт вызывающих не меняется) и отдаём стоимость отдельно. Ошибки входа CLI
печатает в stdout — существующая обработка сохраняется.

### Оценка до рендера

По утверждённому сценарию: символы → секунды через `chars_per_second` из
конфига; секунды × ставка HeyGen + символы × ставка ElevenLabs + плоская добавка
на Клода; всё × наценка. Оценка сознательно грубая и с запасом — её задача не
угадать цену, а не пустить в рендер с пустым балансом.

### Приём вебхука

Отдельный модуль `tribute.py` + HTTP-слушатель на `ThreadingHTTPServer` в
демон-потоке процесса бота (новых зависимостей не вводим; SQLite потокобезопасен
при connection-per-call). Caddy проксирует `tribute.134.209.80.75.sslip.io` на
локальный порт, сертификат выпускает сам.

Подпись: HMAC-SHA256 тела запроса ключом API, заголовок `trbt-signature`.
Сравнение — `hmac.compare_digest`. Тело читать **сырым**, до разбора JSON.

Зачисление считается из полей вебхука `amount` (минимальные единицы) и
`currency` (`usd`/`eur`/`rub`) по курсам из конфига — привязки к ID товаров нет,
поэтому новые номиналы заработают без правки кода.

## Границы

Не входит: реальные выплаты, конвертация валют по живому курсу, Shop API
(доступа нет), возвраты пользователю деньгами, многопользовательские блокировки
сложнее `BEGIN IMMEDIATE`.

Файлы Юли (`compose.py`, `render.py`, `captions.py`, `edit.py`, `zoom.py`,
`revideo_*`, `twin.py`) не трогаем.
