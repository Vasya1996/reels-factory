## 2. Кириллица ломается на трёх уровнях и молча

Это главный технический риск. Ни один из трёх уровней не выдаёт ошибку.

### 2.1 В зашитых шрифтах кириллицы физически нет

`skills/embedded-captions/modes/standard/fonts/fonts.css` — 44 начертания, 24 семейства, 875 КБ woff2, вшиты в base64. Заголовок сгенерированного файла говорит прямо: **`latin subset`**.

Сборщик `modes/standard/fonts/build-fonts-css.cjs` разбирает имена файлов жёсткой регуляркой:

```js
const m = f.match(/^(.*)-latin-(\d+)-(normal|italic)\.woff2$/);
if (!m) { console.error(`[fonts] skip unrecognized filename: ${f}`); continue; }
```

Положить кириллический `.woff2` в `files/` недостаточно — он будет молча пропущен, пока не поправлена регулярка.

Кириллицы нет вовсе в Anton, Bangers, Audiowide, Press Start 2P, Monoton, Special Elite, Permanent Marker, Teko, Creepster, Saira Stencil One. В Inter, Sora, Space Grotesk, Bodoni Moda, Cormorant Garamond, Rajdhani она есть у Google Fonts, но **не в тех подмножествах, что вшиты здесь**.

Какие идентичности задеты напрямую (гарнитура прописана в их DNA или теме): `loud` (Anton), `chrome` (Audiowide), `editorial` (Bodoni Moda), `glitch` (Space Grotesk), `neon` (Orbitron), `velocity` (Teko), `anchor` (Sora), `arcade` (Press Start 2P), `dossier` (Special Elite), `ransom` (Anton + Inter + Special Elite + Permanent Marker), `brush`/`inkwater` (Shippori Mincho), `spectrum` (VT323).

### 2.2 Подстановка шрифтов идёт по семейству, а не по языку

`skills/embedded-captions/scripts/inject-fonts.cjs` смотрит, какие семейства упоминает HTML, и вставляет их `@font-face` из библиотеки. **Ни языка, ни `unicode-range`, ни цепочки фолбэков по письменности в этой логике нет.** Тот же механизм повторён в `make-theme.cjs`.

Их собственный докстринг предупреждает про побочный эффект: рендерер сам подставляет только ~18 канонических шрифтов, всё прочее без локального `@font-face` **молча деградирует на чистой или офлайн-машине** — локально «выглядит правильно» лишь потому, что шрифт установлен в системе.

`render-and-composite.sh` вшивает шрифты **до** гейтов, чтобы измерения были честными. Для латиницы честные и есть. Для кириллицы измеряется уже подменённый системный шрифт — значит гейты overflow и occlusion судят не тот текст, который планировался.

### 2.3 Ширина кириллической буквы считается как ширина цифры «0»

`skills/embedded-captions/assets/fonts/char-widths.json` — таблица измеренных ширин на 24 семейства. Символов ровно 86, одинаковых для всех:

```
0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz.,!?'’":;-–—()[]/&%+#@*
```

Символов выше `U+03FF` — ноль. Фолбэк в `scripts/make-theme.cjs`:

```js
const adv = m ? [...text].reduce((a, c) => a + (m.widths[c] ?? m.widths["0"] ?? 0.6), 0) : text.length * 0.6;
```

Предупреждение `WARN no measured widths` срабатывает только на неизвестное **семейство**, не на отдельный символ. Значит вся геометрия слов на кириллице считается по ширине нуля — без единого сообщения.

**Практический вывод:** зелёные гейты на кириллическом ролике ничего не доказывают. Проверять только осмотром кадров.

## 4. Щель между их жанрами — ровно наш случай

Возможности, нужные для вертикального рилса с живой ведущей, **разделены между двумя скилами и не пересекаются ни в одном**:

| Нужная возможность | faceless-explainer | product-launch-video | pr-to-video |
|---|---|---|---|
| Монтаж реального `.mp4` в композицию | ✗ | **✓** | ✗ |
| Правила вертикальной вёрстки 9:16 | **✓** | ✗ | **✓** |
| Контракт хэндоффа элемента между кадрами | ✗ | **✓** | ✗ |
| Кадры без реальных ассетов | **✓** | частично | **✓** |
| Числовой бюджет длины реплики | ✗ | ✗ | **✓** |

**Единственный воркфлоу, умеющий положить в кадр настоящий видеофайл, — тот самый, у которого вырезан раздел про вертикальную вёрстку.**

Проверяется грепом:

```
grep -c "frame-video" skills/faceless-explainer/scripts/assemble-index.mjs   → 0
grep -c "frame-video" skills/pr-to-video/scripts/assemble-index.mjs          → 0
grep -c "frame-video" skills/product-launch-video/scripts/assemble-index.mjs → 5

grep -rn "portrait" skills/product-launch-video/references/  → нет совпадений
grep -rn "portrait" skills/faceless-explainer/references/visual-design.md → 97, 99, 119
```

Портрет у product-launch-video упомянут только служебно: `scripts/lib/dimensions.mjs:3,10` и `SKILL.md:217`. То есть движок портрет поддерживает, а справочник по вёрстке — нет: в разделе Layout остались только ландшафтные приёмы (split-screen, triptych, asymmetric 60/40), нет якоря `y ≈ 0.42 × height`, нет предупреждения «планируй под формат сразу, не верстай ландшафт с последующей обрезкой».

Хэндоффы `handoff_in:` / `handoff_out:` есть только у product-launch-video (`SKILL.md:131`, `sub-agents/frame-worker.md`). Для роликов, где ведущая визуально продолжается через стык кадров, это ровно недостающий механизм.

**Оба недостающих куска изолированы и одноисточниковые:** раздел `## Portrait & square` — около 8 строк markdown в `references/visual-design.md`; подъём видео — три функции (~100 строк) в `scripts/assemble-index.mjs` плюс абзац в `sub-agents/frame-worker.md`. Файлы у каждого скила свои, правка одного другие не ломает.

Ещё два ограничения product-launch-video, прямо задевающие нас: воркер **не имеет права смонтировать видео сам** — только объявить его для подъёма; и **аудио остаётся за оркестратором** («Audio remains orchestrator-owned: never author `<audio>` in a frame»). Звук ведущей в этой модели идёт не из видеофайла кадра, а отдельной дорожкой через `audio_meta.json`.

Ни один из трёх жанров не содержит слов «avatar», «presenter», «talking head» применительно к содержимому кадра. Живой ведущей как роли в их словаре нет: доступны `cutout` / `background` / `supporting` у PLV и `foreground subject` / `background` / `supporting` у остальных.

**Готовое к переносу:** `captions.mjs` целиком — пословный караоке-таймкод из `audio_meta.json`, плотностный кэп слов (`>3.5 wps → 2`, `>2.5 → 3`, иначе `4`), разрывы по границе кадра, паузе `0.18 с` и знаку конца фразы, хвост `0.12 с`. Субтитры оформлены отдельной суб-композицией на дорожке 2 и ложатся поверх чего угодно, включая видео с ведущей.

## 6. Чего в их документации нет

По этим вопросам прямых ответов не нашлось — рассчитывать на них нельзя:

1. Воспроизводимость авторинга. Нигде не сказано, что один бриф даёт одну композицию; «deterministic» относится только к рендеру.
2. Сквозной путь «конфиг → готовое видео» без агента. SDK есть, примера сборки композиции целиком из структурного описания — нет.
3. Метрики автономности: ни доли успешных прогонов, ни типичного числа итераций.
4. Машинная оценка творческого результата. `lint` и `check` проверяют структуру, рантайм, вёрстку, контраст и motion-intent; «хорошо ли получилось» отдано человеку.
5. Дубляж, перевод, оживление фото, генерация говорящего аватара — ничего.
6. Стоимость: ни цен облачного рендера (только «per credit» и «4k billed at 1.5×»), ни MCP-кредитов, ни HeyGen TTS.
7. Языки и не-латиница: ни страницы про шрифты, кириллицу, иероглифы, RTL или проверку начертаний. Единственное упоминание — поле `language` в контракте брифа: «Use the user's language and state it».
8. Обход лимита 256 KiB для типизированных данных — заявлен, не реализован.
9. Terms of Service и Acceptable Use облачных сервисов HeyGen — в документации HyperFrames их нет, только Apache 2.0 на код.
10. Генерация TypeScript-типов из переменных композиции — только в планах на v1.5.

## 7. Пять технических правил композиции

Их нарушение даёт неправильный рендер (`docs/guides/prompting.mdx:251-257`):

1. Регистрировать все таймлайны в `window.__timelines` — рендерер не перемотает то, о чём не знает.
2. Видеоэлементы обязаны быть `muted`; звук идёт отдельными `<audio>`, чтобы рендерер мог его смикшировать.
3. Никакого `Math.random()` — только seeded PRNG.
4. Таймлайн строится синхронно: ни `async`/`await`, ни `fetch()` при сборке.
5. Элементам с таймингом нужен `class="clip"` плюс `data-start`, `data-duration`, `data-track-index`.

Правила 6–7 (анимация появления в каждой сцене, переходы между сценами) — рекомендации, их можно переопределять.

Две самые частые поломки, по их же словам: анимация размеров видеоэлемента и управление воспроизведением из скриптов. Полный разбор — `docs/guides/common-mistakes.mdx`.
